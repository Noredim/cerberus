📌 Descrição Geral

A API de Integração do OnPremises fornece formas seguras e padronizadas de interação diretamente com as operações do sistema Service. Projetada para facilitar a interoperabilidade, ela permite a consulta e a movimentação de dados operacionais de forma eficiente e estritamente alinhada às regras de negócio da plataforma.

Os endpoints disponibilizados cobrem os principais fluxos de integração operacional, comercial e financeira com o Service, permitindo que sistemas terceiros realizem as seguintes operações:

• Consultas Cadastrais e Operacionais: Acesso padronizado à base de clientes, formas de pagamento, modelos de orçamento e ordens de serviço.

• Gestão de Orçamentos: Criação e registro automatizado de novos orçamentos a partir de prospects, condições comerciais e dados de faturamento.

• Gestão Financeira: Geração de antecipações financeiras vinculadas diretamente a orçamentos existentes, com definição de forma de pagamento, centro de resultados e parcelas.

• Acompanhamento de Ordens de Serviço: Consulta de ordens de serviço e seus dados operacionais, permitindo acompanhar informações como cliente, status, técnico, produtos e serviços relacionados.

Este guia detalha tecnicamente os recursos expostos, incluindo parâmetros de requisição, regras de negócio aplicadas e contratos de resposta (payloads). Para facilitar a implementação, a documentação fornece exemplos práticos de consumo, cobrindo tanto os cenários de sucesso quanto o mapeamento e tratamento de falhas e exceções funcionais comuns.

🔐 Autenticação e Autorização

As rotas de Integrações de Terceiros utilizam autorização customizada por meio do atributo [HashTerceiroAuthorize].

Para consumir as rotas protegidas por esse mecanismo, é necessário utilizar o código hash de terceiros gerado e administrado manualmente no Service, que atua como sistema principal. A API valida esse valor a cada requisição por meio do header HTTP Hash.

O código hash deve ser gerado no Service pelo caminho:

Suporte > B - Configurações > B - Configurador Geral Complemento > aba Geral > botão Gerar Hash

Após gerar o hash, é necessário gravar as informações da tela utilizando o botão Gravar, garantindo que o código fique disponível para validação das requisições realizadas por terceiros.

Portanto, o acesso não depende de autenticação tradicional por usuário e senha. O controle de acesso é realizado pelo hash previamente configurado no Service.

Clientes

📁 Clientes

Conjunto de rotas para consulta e manutenção de dados cadastrais de clientes.

Esses endpoints permitem listar clientes, consultar um cliente específico, aplicar filtros mais detalhados e alterar informações cadastrais. O recurso é útil para integrações que precisam sincronizar cadastros do Service com sistemas externos, atualizar informações de contato, endereço, documento e dados de faturamento, ou validar a existência de clientes antes de executar outros fluxos.

As alterações são realizadas por PATCH, respeitando validações de existência do cliente, obrigatoriedade de identificadores e consistência de campos como documento e tipo de cliente.

📌 Descrição

Retorna uma lista paginada de clientes cadastrados no Service para consumo por sistemas terceiros.

O endpoint é indicado para rotinas de sincronização, conciliação cadastral ou consulta exploratória de clientes.

A resposta é paginada e retorna a lista de registros no envelope padrão da API, junto com metadados de paginação.

📑 Regras e Validações

• A consulta trabalha com paginação.

• Recomenda-se informar pagina, tamanhoPagina e ordenarPor.

• Em consultas paginadas, a API exige ordenação explícita; a ausência de ordenarPor pode retornar falha de validação.

• A ordenação pode ser crescente ou decrescente conforme o parâmetro decrescente.

📌 Descrição

Cria um lançamento avulso de contas a pagar (título) no Service a partir dos dados enviados no corpo da requisição. A rota valida os dados do título, aplica as regras de conta de resultado e conta-caixa, grava o lançamento e seus rateios em uma única transação, e permite reenvio idempotente por identificador externo.

Diferente das rotas de orçamento, esta rota não recebe percentuais de rateio: ela apenas aplica o rateio fixo (por centro de custo ou por empresa) já configurado previamente no Service para a combinação informada — ver a seção "Rateio" em Regras e Validações.

📑 Regras e Validações

Identificação financeira

• O servidor define os campos internos de identificação do título — eles não são enviados pelo cliente.

• planilha usa o contador da entidade no Service.

• numCp usa o contador da entidade configurado no Service, para a Unidade da Empresa, e avança enquanto o número já estiver em uso em ContasPagar ou ContasPagarAgrupadas.

• letra é a primeira posição livre entre 01 e 99 para a combinação empresa + fornecedor + numeroDocumento + serie + operação AvulsoCP.

⚠️ Atenção: as telas locais do Service localizam lançamentos avulsos por empresa, fornecedor, nota fiscal e operação, filtrando Série = 'Avul'. Esta rota preserva a série informada na requisição — uma série diferente de 'Avul' continua válida no financeiro, mas pode não ser listada por essas telas de busca.

Dados gravados no lançamento

• O lançamento é gravado com operação AvulsoCP.

• numeroDocumento é convertido para NotaFiscal (numérico) e para Número (texto).

• contaResultado vai para CentroResultados; contaCaixa para ContaVinculada; observacao para Observações.

• ValorDuplicata, Crédito e Saldo recebem o valor do título; Débito recebe zero.

• DataPagamento permanece nula; Pago, Impresso, Agrupada e Selecionada ficam falsos.

• O usuário gravado no lançamento é API INTEGRAÇÕES.

Conta de resultado

• A SubConta informada em contaResultado deve estar ativa.

• A conta contábil vinculada precisa ter natureza Despesa (D) ou Ativo (A).

• Contas detalhadas são recusadas — exigem informações adicionais que esta rota não recebe.

• Contas marcadas como despesa de veículo também são recusadas quando o controle de despesas de veículo está habilitado na unidade, pois o lançamento exigiria os dados do veículo.

Rateio

• O Rateio será feito conforme configurado previamente no Sistema Service.

• Rateio fixo entre centros de custo grava os percentuais já cadastrados em ContasPagarCentro.

• Rateio fixo entre empresas grava os percentuais já cadastrados em ContasPagarEmpresas.

• Rateio variável — tanto de centros quanto de empresas — é recusado, pois depende de percentuais informados no próprio lançamento, que esta rota não recebe.

• Se o rateio fixo entre centros estiver configurado, mas a soma dos percentuais for zero, a operação é recusada.

• Os centros de custo considerados devem estar ativos e pertencer à unidade 0 ou à unidade da empresa.

Transação e idempotência

• A geração dos contadores, a inserção do título e a gravação dos rateios acontecem dentro de uma única transação, com isolamento Serializable; qualquer falha desfaz todas as alterações.

• Quando identificadorExterno é informado e já existe em ContasPagar, a API retorna o título existente com jaExistia igual a true. Nesse caso, não gera outro título nem consome novos contadores.

⚠️ Atenção: sem identificadorExterno, cada chamada válida gera um novo lançamento — ou seja, repetir a requisição sem esse campo (por exemplo, em um retry após timeout) cria títulos duplicados. Para reenvios seguros, sempre envie o mesmo identificadorExterno (ver seção Reenvio idempotente, abaixo).

Controles que esta rota NÃO aplica

⚠️ Atenção: por dependerem de interação ou liberação gerencial, esta rota NÃO aplica:

• o teto de compras configurado no Service.

• a previsão orçamentária mensal configurada no Service.

• o limite de dias retroativos configurado no Service.

• a efetivação de contas a pagar previstas;

• a conferência de código de barras duplicado.

Se a integração precisar desses controles, eles devem ser garantidos por fora desta rota (no sistema terceiro ou por processo manual no Service).
